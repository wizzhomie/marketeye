    A product name asks the model for candidate pages; a pasted URL skips the model. Each page is fetched and read before it can be watched — a “likely” price is the first of several, so check it before adding.

      How this works

      The collector is deliberately boring and refuses to guess

      • A source is data. Each watched page is a URL plus a parser profile from parsers/profiles.json: a title selector, a price selector and a price pattern. A new site is a profile, not new collector code.
      • One reading per check. The collector fetches the page over HTTP with a plain user agent, reads the title and the price and stores one reading. A missing or unreadable price is stored as an error with the reason — never as a price.
      • One pass a day. ./daily.sh runs the same collection once a day and writes a plain-text digest to data/digests/. Run daily check does that pass right now, so the digest can be seen without a terminal.
      • A new page is a profile. The discovery step asks the model for candidate pages, fetches each one on the server and drafts a parser profile only when it can read a single price. Accepted pages live in data/discovered.json; a demo reset forgets them.
      • One source is real, one is local. books.toscrape.com is a public scraping sandbox: its price stays put. The demo competitor shop is a small HTTP server on this machine whose price moves on after every check, so a price change is visible in the demo.

      Live pages are fetched with their real numbers · no real retailer is scraped · demo only
